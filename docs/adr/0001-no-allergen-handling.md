# 系統不處理過敏原

Google Places 只提供菜系類別與粗粒度標籤（如 servesVegetarianFood），沒有過敏原資料；「花生過敏 → 保證排除」是資料層做不到的承諾，而這是唯一做錯會危及性命的功能。我們決定完全不做過敏功能：條件設定沒有過敏欄位，飲食禁忌僅限 tag 層級可判定者（素食、清真、不吃牛等），UI 不出現任何「已排除過敏風險」的暗示。

## Considered options

- 兩層契約（tag 過濾 + 過敏警語不保證）— 仍會讓使用者誤信系統有在處理過敏，拒絕
- 菜系推斷過敏（海鮮過敏排除海鮮餐廳）— 隱藏過敏原必漏，承諾超過能力，拒絕

## Consequences

- 未來若要加回過敏功能，需要可靠的過敏原資料來源與法律免責設計，不是加一個欄位的事
- 行銷/展示語言必須避免「安全」「保證」等字眼與過敏並列
