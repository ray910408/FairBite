# 沒有群組實體：歷史掛在每人同席紀錄上

跨房間的「近期去過」「曝光統計」「長期公平」原設計掛在 member_set_hash（成員集合的 hash）上，但名單只要多一人或少一人，hash 就全新、歷史全部失憶（四人幫帶一位新朋友，上週吃過的店又高機率出現）。決定：不建任何群組身分 — dining_history 記「每位成員 × 餐廳 × 日期」，近期去過懲罰改為「房內近期吃過該店的成員比例」的函數，曝光與公平 EMA 都以 user 為單位。換人組隊時每個人的歷史照算，且少維護一個概念。

## Considered options

- member_set_hash 精確比對 — 換一人即歸零，被具體情境打臉，拒絕
- hash + 成員重疊率門檻（≥70% 視為同群）— 能解決但閾值武斷、查詢複雜，拒絕
