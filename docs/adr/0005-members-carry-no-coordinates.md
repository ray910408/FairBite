# ADR-0005: 成員不攜帶座標

日期：2026-08-13
狀態：已採納（文件化既有狀態）

## 背景

這是一個定位導向的聚餐決策 app，但只有房主在建房時提供一個座標（搜尋圓心 =
出發點，見 CONTEXT.md）。成員加入（join_room）不收任何位置：引擎裡所有距離計算
都是「圓心 vs 餐廳」，成員座標從未被讀取。PR #9 曾建立「全員座標中位數當圓心」的
整套基礎建設，經實測取捨後回收，圓心改回房主位置、半徑取全員距離偏好平均。

## 決策

成員不攜帶座標，維持為刻意的產品/隱私決策：

- 加入房間不請求定位權限、不傳送座標（少一個權限彈窗、少一類個資）。
- 出發點是「房主替聚會選的集合位置」（可為任選地點），不是任何人的即時位置。
- 個人距離偏好（max_distance_m）仍逐成員生效於半徑平均與距離權重。

## 後果

- 加入流程零定位摩擦；系統內唯一的精確位置只有 rooms.center_*（0015 欄級
  grant 隱藏 + 引擎側量化，見 server/weights.go 威脅模型）。
- 未來若要復活中位數圓心或「對所有人都近」類功能，需重新設計成員位置收集
  （含同意與刪除語意）——本 ADR 是那時的討論起點。
