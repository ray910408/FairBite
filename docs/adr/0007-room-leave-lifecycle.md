# 退房制：回首頁即離席，末位退房即刪房

房間生命週期由「退房（Leave）」收尾：成員返回首頁即退出房間；退出者的投票即刻作廢並在同一交易內重算盤面；房主退出由剩餘成員中最早加入者（`joined_at` 最早，同刻以 `user_id` 決）繼任；最後一人退出即刪除房間。需求方於 2026-08-15 Round 4 brainstorming 裁定，補完 ADR-0004 一次性生命週期缺的「怎麼結束」半場。

觸發點是 HomePage mount（涵蓋瀏覽器上一頁與返回手勢、直接輸網址、關分頁後下次開 app——殘留舊房自癒清除），但 mount 不直接退房：先查房籍，查到房間就跳離席確認，使用者按下確認才送出退房；取消則導回房間，一個請求都不送；房籍查詢失敗時一律不退，改用保守文案讓使用者自己決定，絕不靜默替他按下不可逆的那一步。建房／加入按鈕從 mount 起就禁用，直到確認後的退房請求 settle（或查到根本沒有房籍）才解禁，避免晚到的退房誤刪新房——確認對話框開著的期間正是那個競態。此修訂於 2026-08-16 由 PR #17 的 Codex review 裁定：只在「回首頁」連結上攔截擋不住瀏覽器上一頁、返回手勢與直接輸網址等繞過路徑，而 `leaveRooms()` 是所有路徑的唯一咽喉，在終點攔一次就全覆蓋（`<HashRouter>` + `<Routes>` 非 data router，`useBlocker` 不可用，攔在來源端也只能打地鼠）。房內確認框（RoomPage、HistoryPage）仍然保留——它們警示在導覽發生之前，比事後在首頁補問合理——但按下確認時會隨該次導覽帶一個一次性旗標，讓首頁直接退房而不再問第二次；旗標只在該次導覽有效，重整與上一頁都拿不到。房內確認框的後果文案一律以按下當刻的房籍查詢為準，不讀頁面本地狀態：`useRoom` 在 `rooms` 查詢失敗時會保留過期的房間物件（只亮 `loadError`），而 `POST /api/leave` 是全退不挑房，只講「當前這一間」會漏報殘留房籍。退房走 Go `POST /api/leave`（service role）：刪票屬 vote 寫入、改 `host_id` 屬 rooms 敏感欄位，皆是既有集中寫入路徑的管轄（ADR-0003、0001 欄位凍結），不開 SQL definer 旁路。

意見失效的邊界：退出者的**投票**、**軟性權重**與**硬性條件**都隨退房停止約束盤面——重算（rescore）一律以現任成員的凍結條件重新分割 kept/excluded，離席者的飲食禁忌與預算隨之解除（與其票數、權重失效同一邏輯；分割本來就是活的——「馬上出發」房的營業時間排除亦隨時間翻轉）。真正不回擴的是**檢索集**：搜尋當下未抓回的店（如因其菜系聯集、半徑平均而未檢索者）永遠不會出現，重擴檢索等同重搜，違反一房一搜狀態機。（2026-08-15 eng review outside voice 修訂：原「硬排除不回擴」措辭在現行 rescore 設計下不可維持——下一次投票重算同樣會翻轉分割，維持原措辭需在引擎區分排除來源並與營業時間翻轉互相矛盾，故修訂不變量而非引擎。）

前置：`restaurants_select` RLS 補「自己同席紀錄中的餐廳可讀」條款，讓刪房後足跡頁、偏好學習與補評提示的餐廳參照不降級（restaurants 列永不實刪、`dining_history.restaurant_id` FK 為 RESTRICT，條款永久有效）。

## Considered options

- 只有房主回首頁觸發刪房 — 成員退出無語意，房主一走全滅、成員無繼任；房間生命週期綁死單一人，拒絕
- 任何成員回首頁即刪整房 — 誤觸返回鍵毀掉他人進行中的決策，拒絕
- TTL 排程清理（不做退房） — 房間堆積到排程才清，期間「找不到房間」與「房還在但人早走了」並存，語意混濁；且仍需另解成員中途離開，拒絕
- 退房刪票但不 rescore — 候選排除/機率停在上次投票的快照，被退出者否決的店要等下一票或抽選瞬間才復活，違反「收回後候選即返回轉盤」語意，拒絕

## Consequences

- 房間沒有「閒置」終態:不是走到 `decided` 就是被末位退房刪除；rooms 表長期趨近零殘留
- lobby 之後退房不可重加入（join 凍結，migration 0006）；誤觸退房的代價是重開新房
- 「回首頁＝離席」成為全站導航語意：足跡頁等房內可達頁面需提供不經首頁的入口
- 刪房不抹個人歷史：`dining_history.room_id` 置 null（ADR-0002、migration 0011），餐廳參照由 RLS 的同席紀錄條款長期保證
- 多分頁開首頁會跳出離席確認（2026-08-16 起不再靜默退房）；個人規模接受，不另做分頁互斥
- 離席確認開啟時背景整塊 `inert`：遮罩只擋得住指標，擋不住 tab 順序，沒有它鍵盤使用者能繞過還沒決定的退房
